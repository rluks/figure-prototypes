Reflecting the CFD on the POS

As the Loyalty-on-CFD project lets customers sign up, get assigned to the order, and redeem rewards on the CFD itself, the register needs to reflect what's happening — without turning every step into the blocking pop-up we have today. This is a hybrid: each CFD state is routed to the lightest treatment that fits its urgency. Pick a state to see the recommended routing, or force a single pattern to compare.

The hybrid — which treatment each state gets

Routing follows the state's urgency and where the action happens. The design annotation in the epic spells the loyalty-assignment rule out directly: “0 matches → created → assigned; 1 → assigned; >1 → no [POS notification], because it was done on POS.” Ambient states just need awareness; only states the cashier must resolve earn a blocking popover.

Routing is a proposal, not settled product. Open questions from #proj-cfd-loyalty: is a “customer didn't finish” signal worth a new CFD→POS message? Should rewards show pending-then-confirmed rather than pre-applied? Do multi-profile matches (done on POS) need any CFD-side echo?

The five patterns, compared

PatternFootprintBest forWatch out for
Status stripAmbient · tiny Always-on connection + steady state in one line. Reuses the real 23px StatusBar, cheap to ship. Competes with the existing offline/network strip. One line, no history, easy to miss a change.
Header chipGlanceable · small Live activity tied to the order, where the cashier already looks. Pulses while the customer is acting. Little room for words; needs tap-to-expand for detail.
Mirror cardRich · medium Empathy — cashier sees roughly what the customer sees, so “help them” moments are obvious. Biggest ambient footprint; eats cart space; can pull the eye off ringing up.
Activity feedHistory · medium “What did they actually do?” — added details, signed up, tipped. Good for disputes / training. More than most cashiers need mid-transaction; better as expandable detail than always-on.
ToastEvent-driven · none at rest Speaks only on a change (assigned, disconnected, loyalty-not-applied). Reuses the real Notification. No persistent state — glance away and it's gone. Every-step toasting feels noisy.
Blocking popoverInterrupts · modal The one state that must be resolved now — confirm sign-up, pick a profile, interrupt-to-charge. Today's mechanism. Stops the cashier cold. Justified only when charging can't (or shouldn't) proceed without a decision.
